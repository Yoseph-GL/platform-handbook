# SQL Intermediate: Joins

## Architecture / Rationale

A JOIN combines rows from two or more tables based on a related column. It is the standard way to query normalized data.

Join types:
- **INNER JOIN**: returns only rows that match in both tables (the intersection).
- **LEFT JOIN**: returns all rows from the left table, plus matching rows from the right. Missing matches become NULL.
- **RIGHT JOIN**: returns all rows from the right table, plus matching rows from the left. Missing matches become NULL.
- **FULL JOIN**: returns all rows from both tables. Missing matches become NULL on either side.
- **CROSS JOIN**: returns every combination of rows from both tables (cartesian product). Use with care.

## Query / Code Blocks

```sql
-- CROSS JOIN: every row from employees paired with every row from orders
-- ⚠️ This can produce huge result sets. Only use it when you really need all combinations.
SELECT *
FROM employees e
         CROSS JOIN orders o;

-- INNER JOIN: only employees that have at least one order
SELECT lastname, firstname, orderid
FROM employees e
         INNER JOIN orders o ON e.employeeid = o.employeeid
ORDER BY e.employeeid;

-- Create a rewards table for join demos
CREATE TABLE rewards
(
    rewardid   INTEGER GENERATED BY DEFAULT AS IDENTITY,
    employeeid INTEGER,
    reward     INTEGER,
    month      text,
    PRIMARY KEY (rewardid)
);

INSERT INTO rewards (employeeid, reward, month)
VALUES (3, 200, 'January'),
       (2, 180, 'February'),
       (5, 250, 'March'),
       (1, 280, 'April'),
       (8, 160, 'May'),
       (NULL, NULL, 'June');

-- INNER JOIN: only employees with rewards (both sides must match)
SELECT e.firstname, r.reward, r.month
FROM employees e
         INNER JOIN rewards r ON e.employeeid = r.employeeid;

-- LEFT JOIN: all employees, even those without rewards
-- Employees without a reward show NULL in reward and month
SELECT e.firstname, r.reward, r.month
FROM employees e
         LEFT JOIN rewards r ON e.employeeid = r.employeeid;

-- RIGHT JOIN: all rewards, even those without a matching employee
-- The NULL reward (June) appears, but the unmatched employee does not
SELECT e.firstname, r.reward, r.month
FROM employees e
         RIGHT JOIN rewards r ON e.employeeid = r.employeeid;

-- FULL JOIN: everything from both tables
-- All employees and all rewards appear. Unmatched rows get NULL on the missing side.
SELECT e.firstname, r.reward, r.month
FROM employees e
         FULL JOIN rewards r ON e.employeeid = r.employeeid;

-- CROSS JOIN with rewards: every employee paired with every reward month
SELECT e.firstname, r.reward, r.month
FROM employees e
         CROSS JOIN rewards r;
```

```sql
-- Join comparison reference table
-- Join Type         | Math       | Behavior
-- INNER JOIN        | A∩B        | Intersection: only rows with matches in both tables
-- LEFT JOIN         | Priority A | All rows from the left table. Right-side misses become NULL.
-- FULL JOIN         | A∪B        | All rows from both tables. Misses on either side become NULL.
-- CROSS JOIN        | A×B        | Cartesian product. Every row from A paired with every row from B.
```

## Performance / Optimization Notes

- Always put the JOIN condition in the ON clause, not in the WHERE clause. The optimizer handles ON conditions earlier.
- INNER JOIN is usually the fastest join type because the planner has the most freedom to reorder tables.
- CROSS JOIN on two tables of 10,000 rows each produces 100 million rows. Always check table sizes before using it.
- Use LEFT JOIN with `WHERE right_table.id IS NULL` to find rows in the left table that have no match. This is called an anti-join.
